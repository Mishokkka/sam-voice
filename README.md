# SAM Voice 1.4.4

Модуль для Foundry VTT v13, позволяющий ведущему синтезировать речь через встроенный SAM, локальный Piper, Silero или Qwen3-TTS и воспроизводить её у ведущего и подключённых игроков.

## Сохранение понравившейся реплики

После Preview или Play for All нажмите **«Скачать WAV»** под кнопками воспроизведения. Браузер сохранит последнюю реплику, которая начала звучать у ведущего, без нового обращения к модели. Работает с SAM, Piper, Silero и Qwen.

В файл входят эффекты, скорость и высота голоса, выбранные при воспроизведении, включая хвост эха и реверберации. Последующие изменения текста и настроек не меняют сохранённый вариант. Файл содержит отдельную полную реплику, даже если её остановили; другие одновременно звучащие реплики и звуки игры не подмешиваются.

Под кнопками показан текст доступной записи. Она остаётся доступной после закрытия окна модуля, но заменяется следующей начавшей звучать репликой и исчезает при перезагрузке страницы. Ошибка генерации и ожидание в очереди её не заменяют. Записи, проигранные до обновления модуля, восстановить нельзя.

## Что изменилось в 1.4.3

- `Play for All` получает результат от каждого активного клиента; ошибки и отсутствие ответа видны ведущему. В режиме очереди подтверждается постановка реплики в очередь.
- Клиент с заблокированным звуком сразу отклоняет реплику. Она не запускается неожиданно после следующего клика.
- Stop из окна или API отменяет текущую генерацию, включая подготовку запроса.
- Длина текста проверяется до обращения к модели; тайм-аут сервера показывается как ошибка.
- Проверяются сигнатура аудиофайла и соответствие заявленному формату.
- Исправлен статус события завершения Preview. Кнопки, горячие клавиши, профили и эффекты сохранены.

После обновления все участники должны перезагрузить вкладку Foundry.

## Требования

- Foundry VTT v13, проверено на build 351;
- socketlib;
- для Piper: локальный HTTP backend, по умолчанию `http://127.0.0.1:5050`;
- для Qwen3-TTS: локальный `speech.cpp` сервер, по умолчанию `http://127.0.0.1:8081`.

## Что изменилось в 1.4.0

- `Play for All`, `/sam` и API теперь используют единый путь local + remote. Ведущий слышит ту же реплику, что и игроки.
- Каждый клиент повторно проверяет speech payload перед воспроизведением.
- Ошибки возвращаются в структурированном виде вместо молчаливого проглатывания.
- SAM ограничен 800 символами после транслитерации, Piper 1000 символами.
- Очередь ограничена 20 репликами.
- AudioContext должен реально перейти в `running`. Заблокированный клиент не начнёт неожиданно играть реплику позже.
- Диагностика клиентов имеет тайм-аут 4 секунды на клиента и не зависает из-за одного браузера.
- Piper проверяет MIME, сигнатуру и фактический размер аудио. Лимит transport payload составляет 4 МБ.
- Нелокальные backend URL заблокированы по умолчанию. Разрешение включается отдельно в Module Settings.
- SAM-синтез вынесен в Web Worker с безопасным fallback на основной поток.
- Добавлены request IDs, версия схемы запросов, миграции settings/profiles и ограниченный импорт профилей.

## Использование

Окно открывается кнопкой с роботом в панели чата. Кнопка автоматически восстанавливается после перерисовки Chat Log.

Горячие клавиши в поле текста:

- `Ctrl+Enter`: озвучить всем;
- `Alt+Enter`: локальный preview.

Игрок должен хотя бы один раз кликнуть или нажать клавишу внутри Foundry, чтобы браузер разрешил WebAudio. Статус виден в нижней панели Session Ready.

## API

Совместимый API:

```js
game.modules.get("sam-voice").api.open();
await game.modules.get("sam-voice").api.play("Текст реплики");
await game.modules.get("sam-voice").api.stop();
```

Версионированный API:

```js
const api = game.modules.get("sam-voice").api.v2;

await api.speak("Текст реплики");
await api.preview("Локальная проверка");
await api.stop();
await api.resetAudio();

console.log(api.getStatus());
console.log(await api.getClientStatuses());
```

`api.speak()` и `api.preview()` возвращают объект результата с `requestId`, локальным результатом, ответами клиентов и массивом `failures`.

Legacy chat command:

```text
/sam Текст реплики
```

## Silero (русский TTS на CPU)

Silero добавлен как третий движок, независимо от SAM и Piper. Нужен локальный Python HTTP-сервер (по умолчанию `http://127.0.0.1:5051`) и скачанная модель `v5_5_ru`. В интерфейсе выберите `Silero`, нажмите `Check` и укажите один из пяти голосов: `aidar`, `baya`, `kseniya`, `xenia`, `eugene`.

Полная инструкция: [tools/silero/README.md](tools/silero/README.md). Веса модели не входят в модуль. На всех клиентах Foundry должна быть установлена обновлённая версия модуля; сервер синтеза запускается только у ведущего.

## Qwen3-TTS (естественная русская речь)

Четвёртый движок использует локальный сервер `speech.cpp` с Qwen3-TTS 0.6B или 1.7B. Есть девять голосов и отдельное поле `Voice Instructions` (инструкции поддерживаются только 1.7B). URL сервера, выбранный голос и текст инструкции сохраняются вместе с голосовыми профилями NPC.

Установку и проверку описывает [tools/qwen/README.md](tools/qwen/README.md). Требуется `speech.cpp` с явно разрешённым CORS Origin адресом Foundry. Сервер допускает одну TTS-модель за раз: для замены 0.6B на 1.7B перезапустите его с нужной моделью.

## Piper

Piper генерирует аудио на клиенте ведущего. Готовый файл передаётся игрокам через socketlib. Для длинных реплик предпочтительнее сжатый формат, если backend его поддерживает.

По умолчанию разрешены только loopback-хосты:

- `localhost`;
- `127.0.0.1`;
- `::1`.

Нелокальный сервер получает текст реплик. Включайте `SAM Voice: Allow remote TTS backends` только для доверенного адреса.

## Сборка

Нужен Node.js 22 или новее; для ZIP и тестов Python-сервера — Python 3. Зависимостей npm нет.

```bash
npm ci
npm run validate
npm run package
```

`npm run package` сначала выполняет сборку и JS-тесты, затем создаёт проверенный ZIP в `releases/`. Отдельные тесты HTTP-сервера Silero: `npm run test:silero` (веса и PyTorch не нужны).

Поддерживаемый исходный код находится в `src/samvoice.js` и `src/samWorker.js`. Он восстановлен из опубликованной сборки 1.4.2; оригинальный проект сборки в репозитории отсутствовал. Редактируйте `src/`, затем запускайте `npm run build`. Сборщик копирует код без преобразования логики и вычисляет имя Worker по хешу его содержимого. Результат `dist/` также хранится в Git для установки в Foundry.

`tests/regression.cjs` проверяет генерацию, передачу результатов, отмену, настройки и обработку аудио в изолированном окружении. Если рядом установлен socketlib, дополнительно запускается проверка его настоящего транспорта; путь можно задать через `SAMVOICE_SOCKETLIB_PATH`. Две проверки авторизации отправителя оставлены пропущенными: эта правка не меняет модель доверенного игрового стола. Тесты не заменяют проверку в запущенной Foundry с двумя клиентами.

Foundry загружает `dist/samvoice.js`. Worker SAM находится в `dist/assets/`; оба файла обязательны. ZIP содержит готовые файлы модуля, его нужно распаковать в папку `Data/modules/sam-voice`.
